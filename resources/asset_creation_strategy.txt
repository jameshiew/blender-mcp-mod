Start with get_addon_status and get_scene_info to check the connection, scene,
mode, units, and existing objects. Follow next_offset with the same filters when
you need more objects. Use get_object_info for exact transforms and mesh bounds.

Choose the method that fits the task:
- Use execute_blender_code for procedural geometry, precise edits, materials,
  lighting, and scene setup. bpy is already available. Prefer bpy.data where
  possible; check context and mode before using bpy.ops.
- When an external model is useful, check get_sketchfab_status, search for a
  suitable model, and inspect its preview before importing. Set target_size to
  the intended largest dimension in Blender units and retain attribution.

Group related edits into manageable calls and print a concise summary of changed
objects. Reuse a unique namespace for task helpers and variables; clear it with
reset_namespace and empty code when finished. Namespaces share the Blender scene.

Use get_viewport_screenshot to inspect the initial view when appearance matters
and after meaningful changes. Frame relevant objects first. Screenshots require
a Blender window with a 3D viewport and do not represent a final camera render.
Check object dimensions and world bounds when placement or scale matters.

If code fails, read the traceback and captured output, then inspect the affected
objects before continuing. Earlier changes are not rolled back. A timeout does
not guarantee execution stopped; do not blindly repeat an import or edit.

Finish by checking the affected objects and a screenshot when available. Report
what changed and any verification limits.
